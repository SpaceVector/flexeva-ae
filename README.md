# FlexEva Artifact Evaluation

This repository contains the FlexEva implementation, experiment drivers,
retained results, and plotting scripts used by the paper. Run all commands
from the repository root.

## Layout

| Path | Purpose |
| --- | --- |
| `FlexEva/` | FlexEva implementation used by the experiments; included directly in this repository |
| `large-cluster/` | Real large-scale trace data, including traces from more than 16 GPUs |
| `plot/` | Image output generated by the paper-figure plotting scripts |
| `result/` | CSV files produced by data-bearing experiments |
| `script/` | Experiment entrypoints; each experiment's implementation is grouped under `script/eN/` |
| `trace/` | Trace output from experiments that run on 16 GPUs |

The `script/` directory keeps only runnable entrypoints at its top level:
`run_e1`--`run_e5` run one experiment, `run_all` audits all retained paper
ledgers, and the implementation for each experiment is grouped under
`script/eN/`.

| Experiment | Paper outputs |
| --- | --- |
| E1 | Figure 1 |
| E2 | Table 4, Figure 5 |
| E3 | Figures 6--8 |
| E4 | Tables 6--7 |
| E5 | Table 8 |

E1 setup, replay, and validation instructions are in
[`E1.md`](E1.md).

E2 trace-similarity, evaluator-feedback, and trace instructions are in

## Setup

### Retained-result audit

The checked-in CSV and JSON results can be audited without GPUs:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
script/run_all
```

### Fresh GPU experiments

Fresh runs use the fixed AE server environment:

- Linux x86-64 on GPFS, with at least 20 GiB free;
- eight NVIDIA A100-SXM4-80GB GPUs with full NV12 topology per node;
- Python 3.12.13 with development headers and a shared library;
- PyTorch 2.8.0+cu128 and CUDA toolkit 12.8;
- g++ 11.4.x, CMake 3.22.1, `git`, `make`, `protoc`, `mpicxx`, and
  `nvidia-smi`.

Place the checkout below the GPFS experiment root, select the CUDA-enabled
Python environment, and run:

```bash
export PYTHON_BIN=/path/to/python3.12
script/setup
```

`script/setup` installs the Python requirements, builds the FlexEva extension,
FakeCUDA, CppEvent, the CUDA/NCCL/cuBLAS wrappers, and PRoot, then runs
`script/check_setup`. A successful setup ends with `AE setup: PASS`.

Run setup on every node from the same repository revision. E2 and E3 describe
the additional peer SSH variables for two-node experiments.

## Run

Run from the repository root:

```bash
script/run_all
```

`script/run_all` is a single-host retained-result audit. For fresh runs,
complete setup above and follow the corresponding `E1.md`--`E5.md` guide.

Each script must resolve paths from its own location so execution does not
depend on the reviewer's current working directory. `script/run_e1` is the
single E1 entrypoint. Its default `trace` mode validates the linked 128-GPU
traces and retained ledger; `script/run_e1 real` reruns the five anchors on a
16-node/128-GPU cluster. Both modes write `plot/figure1.pdf`.

`script/run_e2` is the E2 entrypoint. Start it once on node 0; its shared
launcher opens SSH to the guarded second eight-GPU node and returns all native
trace data automatically. Figure 5 uses fresh native CUDA/NCCL execution for
the 8/16-GPU GPT points and every 16-GPU MoE point; its 32/64/128-GPU GPT
points replay the supplied links under `large-cluster/e2/`. Node 0 writes
`result/e2/generated_figure5/<run-id>/` and regenerates `plot/figure5.pdf`.
The optional `table4` mode remains a separate single-node FakeCUDA path.

`script/run_e3` defaults to Figure 6. Figures 6--8 are all coordinator
workflows: configure the peer once, then invoke each command only on node 0.
Figure 6 writes fresh outputs below
`result/e3/generated/figure6/<run-id>/` and regenerates
`plot/figure6a.pdf` and `plot/figure6b.pdf`. Figure 7 uses
`script/run_e3 figure7 self-test`, then `probe` or `run`, and writes below
`result/e3/generated/figure7/<run-id>/`. Figure 8 first captures its local
8-GPU point, automatically starts the peer for both 16-GPU points, then writes
the complete ledger below `result/e3/generated/figure8/<run-id>/`. See
`E2.md` and `E3.md` for the common SSH variables and one-command examples.

`script/run_e4` runs the three Table 6 workload cases and the six Table 7
backend cases; its implementation is grouped under `script/e4/`.

`script/run_e5 paper` collects 32 distinct Routed-MoE candidates and generates
the peak-RSS Table 8 result. The `audit` and default `run` modes reproduce the
archived submitted ledger; all E5 implementation is under `script/e5/`.
