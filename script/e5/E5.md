# Experiment E5: candidate-state memory and per-round speedup

E5 evaluates Claim (C5), regenerates Table 8, and measures the Section 7.5
case-study speedup with one paired ratio per candidate round. The primary
memory output is [`result/e5/table8.csv`](../../result/e5/table8.csv); the paired
speedup output is
[`result/e5/paper_aligned_20260901_r3/speed_per_round.csv`](../../result/e5/paper_aligned_20260901_r3/speed_per_round.csv).
The former submitted ledger remains below `result/e5/submitted/` as a separate
historical audit contract.

## Preparation

The paper-scale path uses 32 distinct routed-MoE source candidates. The anchor
forces route `(0,1)`; candidates use the first 32 distinct ordered top-2 expert
routes other than the anchor. Every candidate has unique routing and dispatch
source partitions, source hashes, a raw-trace fingerprint, and a lineage edge
to the shared anchor. K=1, 8, and 32 always select the same ordered prefixes.

The recovered evidence does not contain the paper's authoritative “different
parallelism” candidate manifest. The executable population therefore keeps
world size 16, EP=8, and DP=2 fixed and varies source-level routing. E5 does
not describe these candidates as 32 different parallelism configurations.

Fresh FakeCUDA capture runs one anchor plus all 32 candidates at 16 logical
ranks with EP=8. It grounds candidate identity, source lineage, and route
behavior, and writes 16 rank traces plus 16 marker files and a SHA-256
fingerprint for every case. The capture uses a reduced 2-micro-batch, 2-layer,
sequence-64, hidden-128 workload because full paper-shape JSONL capture would
require hundreds of GiB. The subsequent reference-method measurements use the
paper shape:

- 16 logical ranks, EP group size 8, and DP=2;
- 64 micro-batches and 64 layers;
- sequence length 256 and hidden size 512;
- 32 ordered source candidates;
- three isolated paired repeats.

### Table 8 memory method

K=1, 8, and 32 distinct candidate states are kept resident in one child
process. Maya-full retains raw events, a full trace, and feedback per
candidate. Maya-trace-RAS retains the complete active-lane-grouped trace and
feedback. FlexEva retains one shared anchor plus each candidate's source
hashes, selected partitions, selected trace, and feedback.

The primary Table 8 metric follows the caption: process-lifetime peak RSS
delta from Linux `ru_maxrss`, measured relative to the pre-construction child
baseline. Post-construction `VmRSS` after GC and `malloc_trim` is secondary.
The final column is
`(median RSS(K=32) - median RSS(K=1)) / 31` MiB per additional candidate.

### Per-round speedup method

For candidate round `i`, the primary metric is

```text
speedup_i = Maya-full_i / FlexEva-refresh_i
```

Maya-full measures full paper-shape event generation, full trace construction,
and full replay. FlexEva measures source diff and AL planning, selective event
generation for the affected `routing` and `dispatch_collective` partitions on
EP representatives `[0,8]`, selected-trace construction, and selected replay.
The cached anchor partition contribution is built using the Algorithm 1
initialization path and excluded from the primary metric. The resulting
anchor-delta feedback must equal Maya-full feedback.

Each candidate/repeat pair runs in a fresh subprocess. Maya-first and
FlexEva-first order alternates to reduce order bias. Each round is represented
by the median of its three paired ratios; the reported case-study result is the
distribution across those 32 round medians. Ratio-of-totals and the cumulative
ratio including one anchor are secondary diagnostics, not the per-round
headline metric.

```bash

```

Verify an existing generated result without rerunning the experiment:

```bash
E5_RESULT_ROOT=/path/to/result script/run_e5 paper-verify
```

The guarded command performs the following sequence without reusing traces:

1. build the frozen C++17 evaluator;
2. capture one anchor and 32 distinct FakeCUDA route cases;
3. hash and validate every trace/marker set;
4. construct the 32 paper-shape candidate specifications;
5. run 27 isolated Table 8 RSS probes;
6. generate and verify peak- and retained-RSS tables;
7. run 32 candidate rounds with three paired repeats;

## Results

### Table 8

| Evaluator | K=1 | K=8 | K=32 | Marginal RSS/candidate |
| --- | ---: | ---: | ---: | ---: |
| Maya-full | 0.62 GiB | 2.93 GiB | 10.73 GiB | 334.03 MiB |
| Maya-trace-RAS | 0.27 GiB | 0.47 GiB | 1.14 GiB | 28.95 MiB |
| FlexEva | 0.27 GiB | 0.27 GiB | 0.67 GiB | 13.39 MiB |

At K=32, FlexEva reduces peak RSS by 93.7% relative to Maya-full and 41.2%
relative to Maya-trace-RAS. The K=32 state-construction wall ratio is 11.22x;
it is an aggregate memory-harness diagnostic and is not the case-study
speedup.

### Per-round speedup

| Statistic over 32 round medians | Result |
| --- | ---: |
| Mean | 13.104x |
| Median | 13.095x |
| Min--max | 12.730--13.350x |
| Q1--Q3 | 13.046--13.186x |
| IQR | 0.140x |
| Population CV | 0.94% |

The mean per-round Maya-full and FlexEva-refresh times are 5.374 s and 0.410
s. The secondary ratio of the 32 round-median totals is 13.096x. Including one
1.961 s anchor initialization gives a cumulative round-32 speedup of 11.394x.
All 96 paired samples have zero feedback-relative error in the reference
model.

This result does not reproduce the submitted 2.48x. It shows a stable 13.10x
paper-scale reference-method speedup for the recovered route-mutation
population. It does not establish the unrecovered production end-to-end
contract because full paper-shape FakeCUDA capture, the original
different-parallelism manifest, and an independent production selective
executor are unavailable.

Compact measurements, integrity decisions, hashes, and tables are retained in
[`result/e5/paper_aligned_20260901_r3/`](../../result/e5/paper_aligned_20260901_r3/).
The complete raw traces remain on the experiment server.

## Matching criterion

Memory verification requires:

- the exact paper state shape and K set;
- 32 distinct candidate IDs, routes, hashes, and source lineages;
- 33 successful fresh captures with 32 files and a non-empty fingerprint each;
- 27 measurements from three isolated repeats;
- positive peak and retained RSS deltas;
- K=32 peak RSS greater than K=1 for every evaluator;
- no adjacent peak-median decrease larger than 1 MiB;
- recomputed medians, endpoint slopes, and three-row CSV equality.

Speed verification additionally requires:

- exactly 32 ordered rounds and 96 paired samples;
- three repeats per candidate with no subset projection;
- `speedup_i` recomputed from its paired Maya/FlexEva times;
- changed partitions exactly `routing` and `dispatch_collective`;
- active-lane representatives exactly `[0,8]`;
- feedback-relative error at most `1e-9`;
- independently recomputed 32-round distribution and CSV equality.

The machine-readable integrity files explicitly mark the result as a
paper-scale reference-method measurement rather than a recovered production
end-to-end reproduction.
