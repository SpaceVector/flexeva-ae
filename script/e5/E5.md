# E5: Table 8 and per-round speedup

Run E5 once on the coordinator:

```bash
script/run_e5
```

The entry point starts an eight-GPU server run. It builds the E5 C++
evaluator, captures one Routed-MoE anchor and 32 distinct route candidates,
constructs the candidate manifest, measures memory scaling at K=1, 8, and 32,
and measures one paired Maya-full/FlexEva ratio for every candidate round.

The measurement shape is:

- logical world size 16, expert parallel size 8, and data parallel size 2;
- 64 micro-batches, 64 layers, sequence length 256, and hidden size 512;
- 32 ordered source candidates;
- one isolated Table 8 memory measurement per evaluator/K combination;
- three isolated paired repeats for the per-round speedup measurement.

The driver validates candidate identity, trace completeness, memory-table
arithmetic, 32-round coverage, paired timing arithmetic, selected partitions,
and feedback equality before the run completes.

Full captures stay below the server run directory because they are large. The
compact outputs are copied to:

```text
result/e5/generated/<run-id>/
  table8.csv
  speed_per_round.csv
  measurement/
    measurements.csv
    summary.csv
    table8.csv
    result.json
    integrity.json
  speed/
    samples.csv
    per_round.csv
    summary.csv
    result.json
    integrity.json
```

Set `E5_RUN_ID` to choose the run identifier. Existing output is never
overwritten.

For CPU-only driver checks:

```bash
script/run_e5 self-test
```

To verify a complete guarded result directory without rerunning measurements:

```bash
E5_RESULT_ROOT=/path/to/e5-paper-aligned script/run_e5 verify
```
