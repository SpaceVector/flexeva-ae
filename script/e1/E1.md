# E1: Figure 1

E1 reproduces Figure 1(b)--(c) from five historical sparse-MoE optimization
rounds. The original experiment used 16 nodes and 128 GPUs. The reviewer
server has 16 GPUs, so E1 does not rerun the workloads there.

Run:

```bash
script/run_e1
```

`script/run_e1 trace` is equivalent. The command performs these steps in
order:

1. validate the five linked 128-GPU CUDA/NCCL trace sets;
2. compare trace timing and communication trends with the historical ledger;
3. validate the ledger arithmetic and paper outcome checks;
4. generate Figure 1(b), Figure 1(c), and the PDF.

The command stops before generating the figure if trace validation fails.
FakeCUDA and the current reviewer GPUs are not used to produce E1 metrics.

## Inputs

The raw trace root defaults to:

```text
large-cluster/e1/historical_sparse_moe
```

On the reviewer server this is a link to the mounted trace tree. Override it
when the same data is mounted elsewhere:

```bash
E1_TRACE_ROOT=/path/to/historical_sparse_moe script/run_e1
```

Each round must contain a merged `capture_manifest.json`, 128 non-empty rank
traces, 128 non-empty marker files, and one valid measured-step window for
every rank. E1 uses only the `gpus_128` trace directories.

The historical ledger is:

```text
large-cluster/e1/trajectory.csv
```

It records the exact Figure 1 values and the SHA-256 fingerprints of the
original benchmark result, patch, and log sources. It is an experiment input,
not a generated result.

## Validation

For every round, trace validation checks:

- `world_size == 128`;
- the manifest was merged from 16 node-local captures;
- ranks 0--127 all have trace and marker files;
- all 128 measured-step windows are paper-valid;
- each marker file contains one matching training-step begin/end pair;
- rank 0 has NCCL send events inside the measured window.

Rank-0 marker duration is used only to verify the Time improvement direction.
The paper Time value is the historical 128-rank maximum step time recorded in
the ledger. The two values use different timing scopes and need not be equal.

Rank-0 A2A trace volume is the sum of NCCL send payload bytes in the measured
window. Its normalized trajectory must differ from the ledger trajectory by
no more than 0.02.

CUDA/NCCL traces do not contain tensor values, so they cannot reconstruct
token Drop or Reroute. Those values, along with historical patch sizes, come
from the fingerprinted ledger after trace validation succeeds.

## Outputs

The run writes:

```text
result/e1/generated/<run-id>/
  trace_validation.csv
  trajectory.csv
  figure1b.csv
  figure1c.csv
plot/figure1.pdf
```

Set `E1_RUN_ID` to choose the run identifier. Existing output is never
overwritten.

Figure 1(b) contains historical Added, Deleted, and Total patch lines. Figure
1(c) contains Time, A2A, Drop, and Reroute normalized as:

```text
reduction = (Base - Candidate) / Base
improvement = 1 + reduction
```

This is a normalized reduction, not `Base / Candidate` speedup.

## Individual checks

On the reviewer server:

```bash
python3 script/e1/validate_traces.py --check-only
python3 script/e1/derive_results.py --check-only
```

The second command validates ledger arithmetic without reading the trace. The
first command requires access to the mounted 128-GPU trace tree.
