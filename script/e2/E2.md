# Experiment E2: trace similarity and evaluator feedback error

E2 reproduces Table 4 and Figure 5(a)--(b), evaluating Claim (C2). Table 4
measures Maya/FlexEva trace similarity. Figure 5 measures evaluator runtime
error. Small scales run on real GPUs; scales beyond the 16-GPU AE server use
the supplied large-cluster traces.

## Figure 5 data sources

| Panel | Point | Ground-truth source |
| --- | --- | --- |
| Figure 5(a) | 8 GPUs | fresh native CUDA/NCCL run on node 0 |
| Figure 5(a) | 16 GPUs | fresh native CUDA/NCCL run across both 8-GPU nodes |
| Figure 5(a) | 32 GPUs | linked `large-cluster/e2/gpt-32` trace |
| Figure 5(a) | 64 GPUs | linked `large-cluster/e2/gpt-64` trace |
| Figure 5(a) | 128 GPUs | linked `large-cluster/e2/gpt-128` trace |
| Figure 5(b) | all five 16-GPU MoE cases | fresh native CUDA/NCCL runs across both nodes |

Every point then uses a fresh FakeCUDA emulation of the matching workload,
the supplied independent estimator, and Maya-lite `prepare`/`simulate` to
produce predicted and actual runtimes. `collect_figure5.py` recomputes the
error, verifies the trace world size and provenance, and only then writes the
CSV consumed by the plotting script.

The checked-in `result/e2/figure5a.csv` and `figure5b.csv` are retained
paper-value references. They are not the default plotting input and cannot
stand in for a missing native run or large-cluster trace.

## Preparation

Figure 5 requires two server nodes with eight physical GPUs each. From the
coordinator checkout, complete the root README's single-command setup. It
creates the peer checkout when needed, verifies the revision, and prepares
both nodes. The FlexEva source is included in this repository.

Besides the normal FakeCUDA/PRoot path, setup builds CppEvent and the real
CUDA, NCCL, and cuBLAS interposition wrappers used by `capture_real`.
The uv-managed Python includes the matching development headers and shared
library.

All later commands run only on the coordinator. `script/setup` stores the
preconfigured peer connection and filesystem settings in an ignored local
profile; reviewers do not need to export them.

The independently trained estimator is included at
`large-cluster/e2/estimator.json`; it is separate from every evaluation trace.

## Execution

Start the normal E2 entrypoint once on node 0:

```bash
FIGURE5_RUN_ID=figure5-production-01 script/run_e2
```

The coordinator opens SSH in batch mode, guards both 8-GPU nodes, starts both
workers, transfers node 1's native trace and marker files over the control
connection, and performs merging, evaluation, validation, and plotting on node
0. No command is entered manually on node 1, and the two checkouts do not need
to share a filesystem.

Figure 5 is the default. Table 4 remains an independent path and runs once on
node 0:

```bash
script/run_e2 table4
```

The Figure 5 path performs this sequence:

1. Node 0 captures the 8-GPU GPT real trace with `capture_real`.
2. Both nodes capture and merge the 16-GPU GPT trace.
3. Both nodes capture and merge the five 16-GPU Routed-MoE traces.
4. Node 0 validates and loads the linked 32/64/128-GPU traces.
5. Node 0 generates the matching emulated trace for every point and runs
   Maya-lite `prepare` and `simulate` with the independent estimator.
6. `collect_figure5.py` builds the two generated CSVs, validates their source
   modes and arithmetic, and `plot_figure5.py` writes `plot/figure5.pdf`.

Completed native captures and evaluations can be reused explicitly under a
new guard run ID by pointing both nodes at those complete directories:

```bash
export FIGURE5_REUSE_NATIVE=1
export FIGURE5_REUSE_EVAL=1
export FIGURE5_TRACE_ROOT=/path/to/node-0/complete/trace-root
export FIGURE5_RESULT_ROOT=/path/to/node-0/complete/result-root
export FIGURE5_PEER_TRACE_ROOT=/path/to/node-1/complete/trace-root
export FIGURE5_PEER_RESULT_ROOT=/path/to/node-1/complete/result-root
```

The default is fail-closed: existing partial output is not silently mixed into
a fresh run.

## Workloads

Figure 5(a) uses the migrated paper GPT trace-shape workload with global batch 768,
sequence length 256, hidden size 512, 64 layers, eight heads, 64
micro-batches, BF16, and a 1f1b pipeline schedule.

| GPUs | TP/PP/DP |
| ---: | --- |
| 8 | 1/8/1 |
| 16 | 2/8/1 |
| 32 | 4/8/1 |
| 64 | 8/8/1 |
| 128 | 8/8/2 |

Figure 5(b) uses world size 16, EP=16, DP=1, global batch 16, sequence length
64, hidden size 128, two layers, 16 experts, top-2 routing, capacity factor
1.25, and BF16. The base seed is 1234; the four route cases use seeds
5200--5203 and expert pairs `[0,1]`, `[0,8]`, `[0,15]`, and `[7,8]`.

Table 4 remains separate. Its GPT cases are 8/16-rank trace-shape workloads,
and its four Routed-MoE cases exercise the same forced expert pairs. The
drivers write fresh FakeCUDA traces under `trace/e2/table4/`, then
`collect_table4.py` writes `result/e2/table4_from_trace.csv`.

## Outputs and checks

A complete Figure 5 run produces:

```text
trace/e2/figure5/<run-id>/gpt/{8,16}/real/
trace/e2/figure5/<run-id>/gpt/{8,16,32,64,128}/emulated/
trace/e2/figure5/<run-id>/moe/<case>/{real,emulated}/
result/e2/generated_figure5/<run-id>/gpt/<scale>/simulate_summary.json
result/e2/generated_figure5/<run-id>/moe/<case>/simulate_summary.json
result/e2/generated_figure5/<run-id>/{figure5a,figure5b}.csv
plot/figure5.pdf
```

Acceptance requires:

- 8/16-GPU GPT and every MoE trace to carry native `capture_real` provenance,
  with one non-empty trace and marker file per rank;
- 32/64/128-GPU GPT rows to use only the corresponding `large-cluster/e2`
  links and contain exactly 32, 64, and 128 rank traces;
- positive predicted and actual runtimes, exact recomputation of
  `100 * abs(predicted - actual) / actual`, and GPT error below 4%;
- Figure 5(b) to contain exactly the five configured 16-GPU native cases.

For a small code-path check that does not require GPUs or supplied traces:

```bash
.venv/bin/python script/e2/collect_figure5.py --self-test
.venv/bin/python script/e2/validate_results.py --check-only
```
