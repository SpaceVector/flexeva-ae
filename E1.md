# Experiment E1: MoE agentic optimization trajectory

E1 covers the MoE agentic optimization trajectory and the data-backed panels
of Figure 1(b)--(c). Figure 1(a) is the paper's workflow illustration and has
no numerical result ledger.

## Execution modes

E1 has two modes:

- `trace` (default) validates the linked historical 128-GPU traces before
  deriving the submitted ledger and figure. The expected link is
  [`large-cluster/e1/historical_sparse_moe`](large-cluster/e1/historical_sparse_moe).
- `real` reruns the five retained anchor workloads on 16 nodes with eight GPUs
  per node, builds a fresh ledger from the measured rank-0 summaries, and
  regenerates the figure. It reruns the generated anchors, not the external
  code-generation API calls that originally produced them.

## Setup

- Code-generation model: `qwen/qwen3.5-plus-02-15`.
- Workload: synthetic sparse-MoE training, starting from a GShard-style
  top-2 baseline.
- Seed: `1234`.
- Historical execution: world size `128`, two training iterations, one warmup
  step, and one measured step per stage.
- Mutation stages: `Base`, `S1`, `S2`, `S3`, and `S4`.
- Plot dependency: install [`requirements.txt`](requirements.txt) before
  generating the PDF.

The five immutable workload snapshots used by real mode are under
[`script/e1/workload`](script/e1/workload).
The original prompts and model responses that generated stages S1--S4 are
retained under
[`script/e1/agent_interactions`](script/e1/agent_interactions/README.md).
They document the historical agent loop but are not replayed by either E1
execution mode.

The retained ledger is [`result/e1/trajectory.csv`](result/e1/trajectory.csv).
It records the mutation labels, code-delta counts, measured step time,
estimated A2A bytes, dropped/rerouted tokens, source fingerprints, and the
normalization fields used by Figure 1(c). The CUDA/NCCL traces independently
validate 128-rank coverage, step-time direction, and the normalized A2A
trajectory. Drop/reroute counts and code deltas remain benchmark/patch fields
because they are not encoded in the traces.

## Default trace execution

From the repository root:

```bash
python3 -m pip install -r requirements.txt
script/run_e1
```

This is equivalent to `script/run_e1 trace`. The command validates the linked
traces and ledger, writes
`result/e1/trace_validation.csv`, regenerates
`result/e1/figure1b.csv` and `result/e1/figure1c.csv`, and writes the combined
Figure 1(b)--(c) PDF to `plot/figure1.pdf`.

Validation alone:

```bash
python3 script/e1/validate_traces.py --check-only
python3 script/e1/derive_results.py --check-only
```

## Real 128-GPU execution

Use the same CUDA-enabled PyTorch environment on every node and run
`script/setup` (or install the equivalent Python dependencies) before launch.
Run the following concurrently from the same checkout on all 16 eight-GPU
nodes. `FLEXMAYA_NODE_RANK` is the only value that differs between nodes:

```bash
export FLEXMAYA_NNODES=16
export FLEXMAYA_NODE_RANK=<0-through-15>
export FLEXMAYA_MASTER_ADDR=<node-0-address>
export FLEXMAYA_MASTER_PORT=29500
export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
script/run_e1 real
```

The runner executes `Base`, `S1`, `S2`, `S3`, and `S4` sequentially with five
multi-node `torchrun` jobs. It uses the configured master port through master
port + 4. Each job runs two iterations: one warmup and one measured step.

Global rank 0 writes raw summaries under
`result/e1/real/<round>/benchmark_result.json`, then writes
`result/e1/real/trajectory.csv`, `figure1b.csv`, and `figure1c.csv`. The selected
mode always writes the paper-facing output to `plot/figure1.pdf`. Set
`E1_REAL_RESULT_ROOT` when rank 0 should use a different result directory.

The dependency-light real-result/CSV self-check is:

```bash
python3 script/e1/run_real.py --self-test
```

## Acceptance criteria

- Exactly five rows appear in the order `Base`, `S1`, `S2`, `S3`, `S4`.
- Every row records world size `128`, seed `1234`, and one benchmark sample.
- `Total = Added + Deleted` for every mutation stage.
- Normalized improvement uses `1 + (baseline - value) / baseline`.
- Trace mode retains the failed `S2` time regression, and its final `S4` row
  reports `61.30%` time reduction and `95.03%` A2A reduction relative to
  `Base`.
- Every trace round contains 128 non-empty rank files and 128 marker files,
  merged from 16 node manifests with paper-valid step windows.
- Trace marker timing reproduces each stage's improvement/regression direction,
  `S4` is fastest, and the trace-derived normalized A2A trajectory stays within
  `0.02` absolute of the submitted ledger.
- Real mode rejects any launch other than 16 nodes, eight visible GPUs per node,
  and world size 128. Fresh performance values may differ by hardware, but all
  five results must be complete, use one measured step, and satisfy the same
  ledger normalization and patch-accounting rules.
